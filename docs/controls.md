# Actions today

One action per class. The same four are written out, with the current-use note and the framework slice, in [sub-attacks.md](sub-attacks.md). The point is to harden the system, the service, and the workflow before an attacker spends that AI allowance against an agentic defense. Nothing here is a tool purchase, and nothing here is a way to drive a meter.

| Class | Action today |
|---|---|
| Insider seat | Cap each person and each AI tool. Cut the AI seat in the leaver process, with VPN and email. |
| Stolen key | Keep the model key out of the app and off the developer machine as the only copy. A public client key gets its own project. |
| Runaway agent | Cap the tool calls, the loop, and the spend, per agent. A new key per job is not the fix. |
| Agentic Service Degradation | Where the product allows it, give the critical service its own key, wallet, or pool, and a month nobody else spends. Where it does not, do not pretend a second API key split the vendor meter. Cap the tool calls. Group repeated events into one investigation, with a ceiling on how much context that investigation can grow. |

## Order

1. List every agentic workflow and which allowance it spends.
2. Where the product allows it, separate the critical service’s allowance from company chat, the helpdesk, and any public bot. A second API key does not split a Microsoft 365 E5 or E7 Security Copilot inclusion pool.
3. Cap the tool calls, and the spend, for one request. Stop the job when the ceiling hits.
4. Group repeated events into one investigation, with a ceiling on how much context that investigation can grow.
5. Alert on the allowance by identity and by service. A green health check is not that alert.
6. Write down what still runs, and what the human queue takes, when that token’s month is spent.
7. When someone gives notice, cut the work-AI seat with VPN, mail, and badge.

## What a vendor cap does not do

Investigator products already sell a finite allowance. That shows the meter exists. A cap can stop an unbounded invoice. It does not, by itself, keep company chat from spending the month a critical service needs. That split is the fourth action.

The published meters are in [agentic-soc.md](agentic-soc.md).
